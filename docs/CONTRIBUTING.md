# 공용 모델 함께 키우기

여러 감독관이 모은 사진을 합칠수록 AI 안경 판독이 정확해집니다. 이 저장소는 서버 없이 GitHub만으로 그렇게 동작합니다.

## 어디에 무엇이 저장되나

| 무엇 | 어디 | 누가 쓰나 |
| --- | --- | --- |
| 모은 사진 | 감독관 PC의 ZIP 파일 | 그 감독관만 (저장소에 올리지 않음) |
| 학습 페이지에서 만든 모델 (‘이 기기에서 바로 사용’) | 그 브라우저의 저장소 (localStorage) | **그 기기·그 브라우저만** |
| 사진에서 계산한 특징값 캐시 | 그 브라우저의 IndexedDB | 그 기기만 (다음 학습을 빠르게) |
| **기여 파일** (`contributions/*.json`, 특징값만) | **GitHub 저장소** | 모두 — 공용 모델의 재료 |
| **공용 모델·공용 데이터** | 배포된 웹 사이트 (`models/head.json`, `models/base_data.*`) | **모든 기기** |

## 흐름

1. 앱의 **학습 데이터 수집**으로 사진을 모으고 ZIP으로 받습니다.
2. **모델 학습** 페이지에 ZIP을 넣고 학습해 봅니다. ‘내 사진’ 성능을 보고, 정답 폴더가 틀린 사진이 없는지 ‘틀린 사진’ 목록으로 확인합니다.
3. **5. 공용 모델에 기여**에서 동의를 확인하고, 두 방법 중 하나로 `contributions/`에 넣습니다.
   - **바로 적용 (파일 주고받기 없음):** 이 기기에 GitHub 토큰을 한 번 등록하면 **기여 만들어 바로 적용** 버튼 하나로 저장소에 커밋됩니다.
     - 재학습·배포까지 끝나면 페이지에 “공용 모델이 업데이트되었습니다”가 뜹니다.
     - 저장소 관리자나 쓰기 권한을 받은 감독관용입니다.
   - **파일로 올리기:** **기여 파일 만들기** → **GitHub에 올리기**로 웹에서 업로드합니다.
     - 저장소 관리자가 아니면 GitHub가 자동으로 포크와 변경 제안(Pull request)을 만들고, 관리자가 확인한 뒤 합칩니다(Merge).
4. main에 합쳐지면 배포 워크플로(`.github/workflows/pages.yml`)가:
   - **공개 기본 데이터 + 지금까지의 모든 기여 파일**을 합쳐(`training/merge_contributions.py`) 다시 학습합니다.
   - 같은 사람이 학습·시험에 나뉘지 않는 교차검증으로 성능을 재고, **품질 기준**을 통과하면 새 공용 모델과 공용 데이터를 사이트에 배포합니다.
   - 실행 요약(Actions → 해당 실행 → Summary)에 받아들인·거부한 파일과 성능이 표로 나옵니다.
5. 모든 기기는 판독 화면을 새로 고치면 새 공용 모델을 씁니다. 다음에 누가 학습 페이지에서 학습하든 **누적된 공용 데이터 위에** 자기 사진을 더해 학습합니다.

## ‘바로 적용’용 GitHub 토큰

1. [GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token](https://github.com/settings/personal-access-tokens/new)
2. **Repository access:** Only select repositories → 이 저장소만 (먼저 해야 저장소 권한을 고를 수 있음)
3. **Permissions:** 목록이 비어 있으면 **Add permissions** → **Contents** 추가 → **Read and write**로 변경
   - 자동으로 붙는 Metadata: Read-only는 그대로 둡니다.
   - 다른 권한은 필요 없습니다.
4. 만료일을 정해 만들고, 학습 페이지의 토큰 칸에 붙여 넣어 **확인·저장**

- 토큰은 그 브라우저(localStorage)에만 저장되고 `api.github.com`으로만 보내집니다. 사이트나 저장소에는 들어가지 않습니다.
- 다른 감독관에게 바로 적용을 허락하려면, 저장소 **Settings → Collaborators**에서 초대하면 됩니다. 그 사람이 자기 토큰을 만들어 씁니다.
- 함께 쓰는 PC에서는 쓰고 난 뒤 **토큰 지우기**를 누르세요. 토큰이 새었다고 생각되면 GitHub에서 바로 삭제(Revoke)하세요.
- 바로 적용한 기여는 Pull request 검토 없이 main에 들어갑니다. 그래도 합칠 때의 자동 검사와 품질 기준은 똑같이 적용됩니다.

## 기여 파일에 들어 있는 것

- 얼굴의 안경 부분과 양쪽 경첩을 MobileNetV3로 계산한 특징값 2,560개 (int8로 압축), 좌우 반전 포함
- 정답(AI 안경 / 일반 안경 / 안경 없음), AI 안경 기종(수집할 때 입력한 이름), 익명화된 사람 묶음(무작위 값으로 해시), 메모
- **사진, 파일 이름, 수험번호, 고사실 이름은 들어 있지 않습니다.**
- 특징값은 사진으로 되돌릴 수 없지만, 사람 얼굴에서 계산한 값이므로 **사진 속 사람의 동의를 받은 데이터만** 올리세요.

## 품질과 안전장치

`merge_contributions.py`가 파일마다 검사하고, 통과하지 못한 파일은 이유와 함께 빼고 나머지로 학습합니다.
- 형식·특징 버전·크기
- 동의 표시
- 앱이 만든 임베딩인지 (임베딩 크기 검사)
- 이미 있는 특징값과의 중복

새 공용 모델은 아래를 만족할 때만 배포됩니다. 아니면 배포가 멈추고 사이트는 이전 모델을 그대로 씁니다.
- 교차검증 AI 안경 AUC가 공개 데이터 모델보다 0.03 넘게 떨어지지 않음
- 빨간 박스 기준 AI 안경 탐지율 60% 이상

빨간 박스 기준선은 매번 “일반 안경을 빨간 박스로 잘못 표시하는 비율 5% 이하”가 되도록 다시 정합니다.

잘못 올린 파일은 `contributions/`에서 지우면 다음 배포 때 빠집니다.
관리자는 Pull request 단계에서 메모와 행 수를 보고 이상한 기여(한 사람이 수천 장, 정답이 뒤바뀐 듯한 파일 등)를 거를 수 있습니다.
